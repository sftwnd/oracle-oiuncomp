# 0001. Формат сжатия Oracle Installer и строгий декодер

[English version](0001-oicomp-format.md)

## Контекст

Дистрибутивы Oracle 7.3 для Unix содержат файлы, сжатые Oracle Installer: к имени сжатого файла добавлен символ
`_`. Распаковывает их утилита `oiuncomp` из каталога `orainst` дистрибутива. Она существует только в виде
исполняемых файлов для Unix-платформ того времени, а формат сжатия не документирован.

В формате нет сигнатуры, длины исходных данных и контрольной суммы. Поэтому испорченный или оборванный файл можно
обнаружить только по нарушениям в самом потоке кодов.

## Решение

Формат описан ниже и реализован декодером на Java.

| Элемент         | Устройство                                                                                       |
|-----------------|--------------------------------------------------------------------------------------------------|
| Заголовок       | первый байт — наибольшая ширина кода; Oracle Installer пишет 14                                  |
| Коды            | идут подряд без выравнивания, от старшего бита байта к младшему; начальная ширина — 9 бит        |
| Литералы        | коды 2–257 обозначают байты 0–255 (байт + 2)                                                     |
| Сброс           | код 1: словарь возвращается в начальное состояние, ширина кода — снова 9 бит                     |
| Код 0           | не используется                                                                                  |
| Словарь         | записи нумеруются с 258; запись — строка предыдущего кода и первый байт строки текущего          |
| Рост ширины     | после добавления записи с номером 2^n − 1 (511, 1023, …) ширина кода увеличивается на бит        |
| Предел словаря  | записи добавляются, пока номер новой записи меньше 2^max − 1; затем упаковщик выдаёт сброс        |
| Конец           | маркера нет: поток кончается, когда до конца данных меньше бит, чем ширина кода                  |
| Выравнивание    | последний байт дополнен нулевыми битами                                                          |

Распаковщик добавляет запись в словарь на шаг позже упаковщика, после следующего кода. Поэтому упаковщик может
выдать код записи, которую распаковщик ещё не добавил: это ровно следующий номер словаря, а его строка — строка
предыдущего кода и её первый байт.

Декодер строже распаковщика Oracle. Повреждением данных (`OiuncompException`) считаются:

- пустые данные и наибольшая ширина кода вне диапазона 9–16;
- первый код после заголовка или сброса, не являющийся литералом, в том числе сброс сразу после сброса;
- код 0 и код больше следующего номера словаря, а на заполненном словаре — и сам следующий номер;
- остаток данных после последнего кода длиной 8 бит и больше или с ненулевыми битами.

Сигнатуры у формата нет: первый байт — параметр (наибольшая ширина кода), второй — старшие биты первого кода,
то есть первого байта исходных данных плюс 2. Поэтому `Oiuncomp.isCompressed` распознаёт сжатые данные пробной
распаковкой: строгий декодер проверяет заголовок и первые 64 кода, а у более коротких данных — все коды и
выравнивание. Нужен хотя бы один код: на пустых данных упаковщик Oracle завершается ошибкой.

Компоненты:

```mermaid
flowchart LR
    cli[OiuncompCommand: командная строка] --> facade[Oiuncomp: распаковка целиком, распознавание]
    facade --> stream[OiuncompInputStream: поток распакованных данных]
    facade -->|распознавание| decoder
    stream --> decoder[LzwDecoder: словарь и коды]
    decoder --> bits[BitReader: биты от старшего к младшему]
```

`LzwDecoder` и `BitReader` не видны за пределами пакета. Публичный API — `OiuncompInputStream`, `Oiuncomp`,
`OiuncompException` и утилита `OiuncompCommand`.

## Обоснование

- Описание формата восстановлено по коду распаковщика и упаковщика в составе Oracle Installer (модуль `oilz.c`,
  функции `oilzdc` и `oilzec`). Проверка — эталонный упаковщик, написанный по этому описанию: он воспроизводит
  сжатые файлы дистрибутива Oracle 7.3 побайтно, включая файл со сбросом словаря. Распакованный текст совпадает
  с опубликованными текстами тех же сценариев той же эпохи с точностью до правок между версиями.
- Корректный упаковщик не выдаёт кодов, которые декодер считает ошибкой. Проверка этих кодов и выравнивания —
  единственный способ заметить повреждение формата без контрольной суммы.
- Распаковщик Oracle останавливается по заполнению выходного буфера и продолжает работу при следующем вызове.
  В Java ту же задачу решает `InputStream`: декодер выдаёт строку очередного кода, а поток отдаёт её по запросу.
- Строка кода собирается по цепочке префиксов с конца буфера, поэтому её не нужно переворачивать. Префикс записи
  всегда меньше её номера, и цепочка гарантированно кончается литералом.
- Код чужих данных допустим для строгого декодера примерно с вероятностью 1/2, поэтому 64 кода отсекают чужие
  данные с большим запасом, а распознавание читает лишь начало файла. На файлах дистрибутива Oracle 7.3, текстах
  сценариев, исполняемых файлах и jar-архивах ложных срабатываний нет.

## Альтернативы

- **Нестрогий декодер, как у Oracle.** Распаковщик Oracle принимает любой код больше последнего номера словаря
  за «следующую запись» и читает незаполненные записи словаря. На повреждённых данных это даёт мусор без ошибки.
- **Перенос конечного автомата распаковщика Oracle с приостановкой по размеру вывода.** Состояние приостановки
  нужно только при выталкивании данных в буфер вызывающего кода; потоковое чтение делает его лишним.
- **Запуск исходной утилиты.** Нужна старая Unix-платформа или её эмуляция; на современных системах это
  неприменимо.
- **Распознавание по первому байту.** Байт 14 — значение параметра, а не маркер, а допустимый заголовок 9–16
  есть, например, у текста, начинающегося с табуляции или перевода строки.

## Последствия

- Обрыв файла точно на границе кода обнаружить нельзя: формат не хранит длину.
- Сжатые данные должны занимать источник до конца. Поток, в котором за сжатыми данными идут другие, не
  поддерживается: формат не позволяет найти его границу.
- Наибольшая ширина кода в заголовке ограничена диапазоном 9–16. Распаковщик Oracle принимает и значения меньше 9,
  считая их за 9; в известных файлах дистрибутива заголовок всегда равен 14.
- Память декодера — словарь до 65 535 записей и буфер строки: около 384 КиБ при ширине 16 и 96 КиБ при ширине 14.
- Тестовые данные синтетические. Эталонный упаковщик из тестов закрепляет формат: круговая проверка охватывает
  рост ширины кода, сброс словаря и коды записей, которых распаковщик ещё не добавил.
- Настоящие файлы Oracle в проект не входят. Проверка на них локальная: `SampleFilesTest` со свойством
  `oiuncomp.samples` (файл или каталог) требует, чтобы каждый файл распознавался, распаковывался и восстанавливался
  эталонным упаковщиком побайтно.
- Заголовок без кодов распаковывается в пустые данные, но сжатыми не распознаётся.

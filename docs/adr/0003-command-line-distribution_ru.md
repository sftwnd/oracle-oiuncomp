# 0003. Дистрибутив утилиты командной строки

[English version](0003-command-line-distribution.md)

## Контекст

Утилитой пользуются из командной строки, часто для целых деревьев каталогов дистрибутива Oracle. Запускать её через
`java -jar` с путём к JAR в повседневной работе неудобно. Тот же JAR — ещё и библиотека, OSGi-бандл и модуль Java 9+
(ADR 0002), поэтому удобство командной строки не должно его для этого портить. Для запуска утилиты по-прежнему должно
хватать Java 8.

## Решение

- Сам JAR запускаемый. Инструкции bnd задают `Main-Class`, поэтому `java -jar` работает на Java 8+. На JDK 9+
  `maven-jar-plugin` обновляет JAR с дескриптором модуля утилитой `jar` из JDK (plexus-archiver), и она записывает тот
  же класс как основной класс модуля (`ModuleMainClass`): `java -p <jar> -m com.github.sftwnd.oracle.oiuncomp`
  запускается без имени класса.
- Отдельный дистрибутив `oracle-oiuncomp-<версия>-bin.tar.gz` и `.zip` собирает `maven-assembly-plugin`
  (`src/main/assembly/bin.xml`) и присоединяет к проекту с классификатором `bin`:
  - `bin/oiuncomp` — скрипт запуска для POSIX `sh` с правами 0755 и окончаниями строк Unix; чтобы найти свою
    установку, он проходит по символическим ссылкам на себя;
  - `bin/oiuncomp.cmd` — скрипт запуска для Windows с окончаниями строк Windows;
  - `lib/oracle-oiuncomp.jar` — JAR сборки под постоянным именем;
  - `LICENSE`, `README.md`, `README_ru.md`.
- Скрипты берут Java из `JAVA_HOME`, иначе из `PATH`, передают JVM опции из `JAVA_OPTS` и запускают `java -jar`.
- `DistributionIT` проверяет состав обоих архивов, права в tar.gz и окончания строк скриптов, а также запускает
  скрипт для Unix напрямую и через символическую ссылку. `PackagingIT` запускает модуль без имени класса.

## Обоснование

- Основной класс назван в одном месте — в `Main-Class`: основной класс модуля сборка выводит из него.
- `java -jar` в скриптах работает на Java 8, а запуск модуля требует Java 9+.
- При постоянном имени JAR скрипты не зависят от версии: она есть в имени архива и его базового каталога.
- tar.gz сохраняет право на исполнение скрипта при распаковке любым tar; zip сохраняет его лишь для некоторых
  распаковщиков, но это привычный формат в Windows.
- Архивы воспроизводимы: `maven-assembly-plugin` берёт время записей из `project.build.outputTimestamp`, и утилита
  `jar`, которую запускает `maven-jar-plugin`, его тоже сохраняет.

## Альтернативы

- **Самоисполняемый JAR со скриптом запуска в начале файла**, как в Spring Boot. Некоторые инструменты такой файл не
  принимают, скрипт работает только в Unix, а нёс бы его основной артефакт — библиотека, бандл и модуль.
- **Образ `jlink` со своей средой исполнения.** Около 30–40 МБ и отдельная сборка для каждой платформы; лишнее там,
  где Java установлена.
- **Нативный исполняемый файл (GraalVM Native Image).** Отдельный инструментарий и бинарный файл для каждой
  платформы.
- **Только alias в README.** Нет запуска в Windows, и каждый пользователь повторяет настройку сам.

## Последствия

- `package` выпускает ещё два артефакта с классификатором `bin`; `install` и `deploy` обрабатывают их вместе с JAR.
- Для скриптов запуска нужна установленная Java 8 или новее.
- Скрипт для Windows сборка проверяет только на наличие и окончания строк; в Unix он не запускается.
- В JAR, собранном на JDK 8, нет ни дескриптора модуля, ни основного класса модуля, но дистрибутив работает так же.
